# Presentation cache, source and reader inventory

Reconciled on 2026-09-30 against internal iOS main
`bf5914261be4193935ffadc1dce140fa9cf78f6a` for infra #315 / LAV-206. The release
candidate frontend is the full React Native app with its embedded native flows
and extensions. Legacy SwiftUI Activity pages absent from the generated production
source manifest are not a second qualified frontend.

Every private presentation query has a declared policy. Only Activity opts into
native encrypted reuse; other private derivatives use authorized no-store paths.
Identity never supplies authorization. See the
[key and authorization contract](../architecture/presentation-cache-security.md).

The new default-deny query registry and final delivery check prevent an undeclared
bridge read from silently acquiring cache policy. That check does not discover an
arbitrary new native file reader. Adding a source consumer, export, image store,
widget projection or frontend requires updating this inventory and its native
authorization boundary.

Release acceptance remains open for physical Passcode/Face ID, policy toggles,
navigation/lock/background races, account changes, source clears/restores and the
warm p95 500 ms target. At least 30 trials per supported auth method must separate
hits, misses and cold reads across Today/7 days/Month/custom ranges and VPN states.
